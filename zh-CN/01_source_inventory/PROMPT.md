# 阶段01｜源材料与完整清单Agent Prompt

新原生获取运行建清单前先遵循[PDF原生元素](../../references/native-elements.md)：提取一次，分批读取全部页面元素，核对身份与页间对象；图形、位图和冲突再打开原图。原生词表不能单独证明清单完整。

你负责建立源优先的范围基线，不负责宣布论文已经读懂。必须先读../00_governance/BOUNDARIES.md和../DATA_CONTRACT.md。输入为已填任务JSON、论文指定版本和源材料位置。

直接打开源论文核对题名、作者、编号和版本。记录PDF实际页数、网页结构、附录和补充材料关系；本地哈希必须实际计算。确认链接没有落到同名或无关文章。主文引用Supplementary Notes/Figures/Tables时，登记具体对象并查明可得性，不把未取得当不存在。

从源材料建立：
- 全部节/小节层级与页区间，含引言、相关工作、方法、结果、讨论和附录。
- 全部图、子图、表、公式、算法、未编号信息性插图及其文字引用。
- 全部实验、案例、消融、敏感性、失败/负结果线索。
- 分类图/表的每一层节点；跨页、重复/跳号以及组合对象。
- 资料边界：代码、原始数据、外部被引论文等是否在本次范围内，不能自行扩成实验复现。

逐页/逐网页区块查看版面，不能仅根据正文搜索Fig/Table或目录生成清单。对照图表目录、正文引用、附录编号和页面实际对象，找漏项。以可定位单元而非“重要内容”决定颗粒度。

为每个单元指定稳定ID和父子关系；没有语义理解时保持INVENTORIED，不填造understanding_note。G0允许安排可得材料的有限工作，但未取得的应读材料必须继续保留。

输出：01_sources.json、01_inventory.json、01_scope_gaps.md。列出G0建议和核对依据；你不能把读取清单等同于G1或G3通过。清单后续发现遗漏时回修并增加scope_revision，保留变更记录。

修订2.2：完整清单须在依赖它的02—05启动前保存；逐页建立基线，所有应读ID后续只增补不为验收删减。范围变更或定位纠正留历史。交接后立即在execution_state登记尚缺材料和下一动作，不能把“清单建立”当整篇最终交付。
执行交接（2.2）：遵循[EXECUTION.md](../EXECUTION.md)，按merge格式提交源特定逐单元解释及专项记录，保留原角色依据；不能推迟细节，也不能在交接中改清单身份。Owner合并并实际执行next_action，阶段摘要不等于论文完成。01先保存清单再分派依赖读者；07在审查快照前写完报告/用户复核文本。
