# Native PDF elements (revision 2.7; appends and data files 2.10)

Use this contract for runs initialized with `content_acquisition.method=PDFPLUMBER_NATIVE`. Earlier runs through revision 2.6 without that field retain their existing acquisition and visual evidence rules. A revision-2.7 packet missing its acquisition contract is invalid. Do not retrofit an active or frozen run. This changes how source content is obtained, not complete Owner reading or mandatory independent claim coverage. [Appending late sources](#add-sources-acquired-after-extraction-210) and [data-file supplements](#data-file-supplements-210) apply only to runs initialized at 2.10 or later.

## Extract once, read bounded source slices

Start with the [native reading quickstart](section-reading.md#native-reading-quickstart) for `extract-elements`, outline, verified section reading and page diagnostics. Use `read-elements --view text` for a short UTF-8 check of a heading or disputed passage, not a full-text page export. For glyph geometry or a specific object, request bounded **detail**, for example:

```text
python "<skill>/scripts/reading_run_control.py" read-elements "<run>" --source-id SRC-01 --pages 7 --bbox <x0> <top> <x1> <bottom>
```

pdfplumber is an optional dependency of extraction, not of the standard-library controller/checker. Use the host's documented bundled Python when it already supplies the dependency. Other deployments must supply it explicitly. Missing support returns `PDFPLUMBER_UNAVAILABLE`; do not automatically install, download a model, upload a source, enable OCR or silently substitute full-page vision.

New packets bind `content_acquisition` with `method: PDFPLUMBER_NATIVE` and `manifest_ref: source_elements/manifest.json`. Runs initialized at 2.10+ write schema version 2: the fields below plus `data_sources` and an append-only `history`. The schema-version-1 manifest records `parser.name=pdfplumber`, its version, `ocr_used=false` and `sources[]` entries containing source_id, local_path, sha256, page_count and pages[{page,ref,sha256}] for every available local PDF, required or optional. Extraction preserves actual source identity/hash and page-file hashes; source_id disambiguates identical page-local element IDs across sources. Per-page JSON retains source_id, page, width/height, native text, words with IDs/bboxes, tables with IDs/bboxes/rows/cells/flags, images with IDs/bboxes/srcsize, lines/rects/curves and page flags. The text element is p0001-text, with table p0001-t001, image p0001-i001 and word p0001-w00001 ID patterns. Treat object IDs as page-local evidence locators, not semantic labels invented by a model. Files and parser output do not demonstrate that anyone read them.

Read prose by [verified section/subsection](section-reading.md), including in supplements. Physical pages back the evidence and coverage audit; use bounded `read-elements` detail to examine gaps, original objects or extraction conflicts, not to drive body reading. Bounding boxes use PDF points with the origin at the page top-left. Full-page output includes text plus compact table/image/flag summaries; word/geometry detail is requested only for a bbox. Exhausting --max-chars returns ELEMENT_READ_LIMIT rather than silently cutting a page. Extraction caps each PDF at 500 pages and 100 MB and all PDFs at 10,000,000 native characters; PDF_ELEMENTS_LIMIT fails rather than claiming truncated coverage. Encrypted PDFs fail with PDF_ELEMENTS_ENCRYPTED; no password or bypass is attempted. Re-running the first extraction returns ELEMENTS_EXIST (2.10+: register and append instead); source changes return ELEMENT_SOURCE_CHANGED; invalid manifests/pages return ELEMENTS_INVALID. Do not overwrite evidence to make stale records appear current.

## Add sources acquired after extraction (2.10+)

A required supplement often becomes available only after the first extraction. In a run initialized at 2.10 or later, bind it into the same run; do not start a continuation run or re-adopt earlier reading:

1. Acquire it lawfully. Copy the bytes unchanged into the run (for example `supplements/`) together with the retrieval record.
2. Register it in `01_sources.json` with its actual SHA-256, `access_state: AVAILABLE`, `supplement_of` and `required_for_scope`. Use `source_kind: PDF` for PDFs and the [DATA_FILE fields](../en/DATA_CONTRACT.md#1-locators-and-units) otherwise. Inventory its units, then `sync`. The assessment now reports `ELEMENTS_APPEND_REQUIRED`, and readers stay blocked until the append is done.
3. Run `python "<skill>/scripts/reading_run_control.py" extract-elements "<run>" --append`. PDFs need the same provisioned pdfplumber interpreter; data-file-only appends need none.

Append extracts only the newly AVAILABLE sources. Their pages go to a new `source_elements/append-NNNN/` directory. The previous manifest's exact bytes are preserved as `source_elements/history/manifest-NNNN.json` before the manifest is atomically replaced. Each `history` entry records its sequence, operation, parser, source IDs, and the preserved predecessor's path and SHA-256. The validator rejects a changed or missing snapshot, and any earlier source, data or history entry that differs from its snapshot. Existing page files are never rewritten, so checked units on earlier sources keep their evidence. Parser or validation failures are not published. An interruption during publication can leave an unreferenced new directory or predecessor snapshot; the last published manifest remains usable. Concurrent appends return ELEMENTS_APPEND_BUSY. After a crash, confirm the previous writer stopped before removing only the empty `.source-append.lock` directory. An unreferenced `append-NNNN` directory from an interrupted attempt is neither reused nor removed. Report it rather than deleting it.

If an old writer already left a partial file at the reserved predecessor path, do not overwrite it. Back up the run, check the committed chain, then manually quarantine it only if confirmed unreferenced. New publications stage and verify the complete predecessor before exposing its final name.

ELEMENTS_NOTHING_TO_APPEND means nothing new is registered. A required source known but not yet AVAILABLE does not prevent the initial 2.10 extraction of accessible PDFs; the checker still blocks acceptance. A changed bound source still returns ELEMENT_SOURCE_CHANGED and still requires a fresh run. Required sources that remain unavailable stay material blocks. Appending changes the scientific content: prior review snapshots become stale, and outstanding `read-section` cursors restart. Runs initialized before 2.10 return ELEMENTS_APPEND_UNSUPPORTED and keep their original continuation-run route.

## Data-file supplements (2.10+)

Register CSV, TSV, XLSX, JSON, Markdown and plain-text supplements as `DATA_FILE` sources with real provenance and hashes; never convert them to PDF, invent pages, or set them unavailable to satisfy a check. Extraction (first or append) does not open them as PDFs. It verifies the record, the file hash and any ZIP container member, then records a navigation-only `structure` in `data_sources`. A fresh validation recomputes that summary from the hash-verified bytes using the original binding and compares it with the manifest before exposing any data: tables/sheets with row ranges, column counts and first-row values, JSON top-level keys or line counts. Content the standard-library reader cannot represent is recorded as `parse_state: CONFLICT` (for example TEXT_DECODING_CONFLICT, CSV_PARSE_CONFLICT, JSON_DUPLICATE_KEY, XLSX_STRUCTURE_CONFLICT). Units cannot be checked from an unresolved conflict. If the frozen result is specifically TEXT_DECODING_CONFLICT, establish the actual supported encoding, declare it explicitly in `01_sources.json` and `sync` without editing the data, receipt or manifest. Validation must reproduce the old conflict from the same bytes and successfully parse the synced declaration. Readers see the effective structure while the immutable manifest still records what happened at acquisition. This reopens the scope gates and affected units. It does not permit changing the codec of a successfully decoded binding or declaring other representation conflicts resolved.

Read bounded content by file + row/field locator:

```text
python "<skill>/scripts/reading_run_control.py" read-data "<run>" --source-id SUP-S4
python "<skill>/scripts/reading_run_control.py" read-data "<run>" --source-id SUP-S4 --rows 2 40 --fields study_id outcome
python "<skill>/scripts/reading_run_control.py" read-data "<run>" --source-id SUP-XLSX --sheet Screening --rows 1 25
python "<skill>/scripts/reading_run_control.py" read-data "<run>" --source-id SUP-JSON --json-pointer /studies/3
python "<skill>/scripts/reading_run_control.py" read-data "<run>" --source-id SUP-MD --lines 1 80
python "<skill>/scripts/reading_run_control.py" read-data "<run>" --source-id SUP-MD --lines 4 4 --chars 1 500
```

Without a locator the command returns the validated structure for navigation. Oversized selections return DATA_READ_LIMIT; narrow the rows, fields, lines or pointer. If one line, one tabular text value, or one JSON string still does not fit, add `--chars FIRST LAST` (1-based inclusive Unicode characters). Inspect contiguous windows through `total_chars`; `partial: true` is not a complete read. Use one named field, or omit `fields` only for a single-column row. `--chars` is a display window, not a replacement for the source locator. The CLI emits JSON numbers as numbers, preserving their original precision and exponents; consumers must also use a lossless numeric reader. Nothing is silently truncated. The local reader caps data files at 50 MiB, decompressed workbook XML at 100 MiB, and workbook/delimited table cells at two million (including expanded sparse cells). Values are returned as stored. Workbook formulas are not evaluated (their cached values are flagged FORMULA_CACHED_VALUES), and number formats such as dates are not applied. MERGED_CELLS, HIDDEN_SHEET, HIDDEN_ROWS, EMBEDDED_GRAPHICS_NOT_REPRESENTED, EXTERNAL_LINKS_NOT_FOLLOWED and MACRO_PROJECT_PRESENT_NOT_EXECUTED flag content to inspect or report. Record how each relevant flag was resolved in a local `conflict_resolution_refs` note before marking a unit checked. The cell reader does not inspect workbook charts or images. For an informative graphic, inspect a safe original rendering and retain its locator and evidence; if you cannot establish coverage, keep the unit blocked. XML document-type or entity declarations are refused, not parsed. Never run scripts, notebooks, macros or build files from a package, and never enable workbook macros or external links in another application.

For a data TABLE to qualify for structured inspection, the locators must resolve to tabular data (CSV/TSV/XLSX) with actual non-header, nonempty cells. A JSON scalar or a text title cannot establish this. A workbook with unrepresented embedded graphics is not exempt from pixel inspection on the strength of a resolution note. When the exception does not apply, inspect the actual rendering and record its local image/PDF evidence, or keep the unit incomplete. For a valid table read only as cells, keep `visual_review.actually_viewed` false. Data TABLE units required by the review plan need the reviewer's own `structured_inspection`, the same as complete native tables. Data files are hashed into source identity and review snapshots. Changing source bytes or container binding invalidates the binding. The narrow verified decoding correction above is the only exception for an encoding change.

Keep section joins and source locators. Use section chunks and targeted table detail rather than dumping every character, drawing primitive or the complete manifest. Detailed JSON stays on disk for narrow inspection and calculation. Reconcile the outline and inventory with page coverage; extraction is not permission to omit footnotes, references needed for interpretation, equations, appendices or required supplements.

## Locate figures and tables before detailed inspection

Use the read-only locator view on pages with visuals or complex tables. It reads the same validated manifest and page files, without OCR, new dependencies, re-extraction or a new run artifact:

```text
python "<skill>/scripts/reading_run_control.py" read-elements "<run>" --source-id SRC-01 --pages 2 --view locator
python "<skill>/scripts/reading_run_control.py" read-elements "<run>" --source-id SRC-01 --pages 2 --view locator --bbox <x0> <top> <x1> <bottom>
```

The page result points back to the original PDF (`source_ref`), physical page, its size in PDF points and the full native record (`page_ref`). `objects` lists embedded bitmaps (native ID and pixel size), detected tables (native ID, row count and flags), and approximate `drawing_region` boxes (grouped native primitives, not classified charts). A drawing anchor identifies **one primitive**, not a whole figure or panel. When nearby parallel rules and a numbered table caption are the only usable drawing cues, `basis: parallel_rules` suggests a crop; it supplies no table ID or cell values. Use the coordinates to open a legible crop of the original page. No image pixels, cell matrix or per-glyph paths are sent in this view.

A bbox narrows the search, counts local primitives and adds a native-word preview (up to 240 characters). `caption_hints` are numbered line starts nearby, including above/below the crop, with word IDs, boxes and first-line previews; `preview_shortened` marks clipped previews. These are candidates, not verified associations: confirm the caption, panel, continuation lines, table notes and relevant body footnotes on the source. Missing candidates can mean a missed borderless table, an unnumbered figure or labels baked into pixels. Rules, logos or several adjacent panels can form a drawing region, and chart gridlines can be misdetected as a table. Treat the shape and kind as hints, not a reason to skip pixels. Never infer absence or coverage from a locator list. If the response exceeds `--max-chars`, narrow the page/region; no object list is silently truncated.

For detailed object inspection, omit `--view` (or use `--view detail`) and inspect the specific saved page/table record by ID when detail is too large. For a graphic or conflict, `render-crop` takes **one physical page**, the verified bbox in top-left PDF points and a new run-relative PNG path. Its receipt gives `path`, `physical_page`, `source_id`, `source_sha256`, `bbox`, `image_sha256`, `pixel_size`, `scale` and `reading_state_changed=false`. Open **that file** with an image-capable viewer and inspect it alongside the caption/context. If the crop cuts off a label or panel, correct the box and open the new crop; if pixels are unavailable, record the gap. Neither a locator nor a render/hash establishes a visual observation.

## Choose the evidence route per object

| Source content | First evidence | Additional inspection |
|---|---|---|
| Body text, captions, native labels | Text/word records and page coordinates | Reopen a crop or alternate native extraction when order, spacing, encoding, superscripts or attribution are unclear |
| Complete native table | Every extracted cell, row/column relation, header, units and notes | Inspect the original when cells are missing/merged incorrectly, emphasis matters, a region contains raster content, or structure/text conflicts |
| Equation or algorithm | Native glyphs, layout and adjacent definitions | View a legible crop when symbol identity, fraction/script structure or reading order is ambiguous; native text is not guaranteed LaTeX |
| Raster chart, photo, screenshot or qualitative image | Its actual embedded-image region and surrounding native caption/context | Actually view source pixels; native captions/labels cannot substitute for image content |
| Vector graphic, plot or flowchart | Native labels plus available lines/curves/coordinates | Actually view its graphical relationships; drawing primitives alone do not establish arrow direction, groups, statistical comparisons or causal meaning |

`LABEL_ONLY` evidence never establishes plotted values or relationships. A raster chart may have no native internal labels at all. Do not turn a caption, an image bounding box or an approximate pixel estimate into an exact data value. If a lawful source table/data file is actually available, preserve its provenance separately; do not execute paper code or expand source access implicitly.

Native extraction can join words, break reading order, map glyphs incorrectly or split/merge tables. Preserve the observed conflict and its exact source location. Resolve it with existing native alternatives and/or direct visual inspection, retaining a local resolution note. Per-page `chars` retain glyph IDs, text, coordinates, font and size; bbox reads include glyphs for narrow formula/encoding checks. A GLYPH_MAPPING_CONFLICT or NO_NATIVE_TEXT page requires actual pixel evidence and a resolution note for the affected unit. Unresolved reading conflicts remain reading gaps; a parser's successful return code is not a resolution.

## Owner records and the narrow table exception

Every checked **PDF** unit in a new acquisition run records `content_reading` with mode `NATIVE_ELEMENTS`, `VISUAL` or `MIXED`, existing `page_refs`, precise `element_ids` and `conflict_resolution_refs` where a conflict required resolution. NATIVE_ELEMENTS means source-native content was actually read; VISUAL means required pixels were actually read; MIXED retains both. None is assigned from extraction alone. References must resolve to the bound source/page and actual elements covering that unit. A unit does not become CHECKED automatically after extraction.

A TABLE can satisfy its content inspection through verified native elements only when its manifest/source binding is current, table IDs and page locators match, every informative cell/header/note is covered, no bitmap overlaps the table and no unresolved table/page extraction conflict remains. Preserve `visual_review.actually_viewed=false` if no pixels were viewed; the native record is an honest alternative, not a fabricated viewing flag. If those conditions fail, perform and record actual visual inspection or keep the unit incomplete.

The exception is TABLE-specific. FIGURE, PANEL and OTHER_VISUAL relationships still require genuine viewing. All in-scope text, table content, formalism, methods, experiments and graphical objects remain part of complete reading. Ordinary text pages do not require rasterization merely to establish reading.

## Independent review and snapshots

The reviewer establishes its own source-first map from the native source evidence before draft conclusions, checks the complete Owner inventory and verifies every claim required by the selected review mode. It reads mandatory native textual/table evidence itself. For mandatory native tables accepted without pixel viewing it records its own `structured_inspection` with inspected `unit_ids` and local reviewer `evidence_refs`; ordinary text continues to use actual checked unit/claim coverage and source evidence. Owner reading flags do not become reviewer inspection.

Direct reviewer pixel evidence covers the mode-required graphical, raster and conflict objects. A validated native table can use the table exception instead; it must be covered by the reviewer's own structured inspection. A source with no pixel-required objects does not need a fabricated image-capability probe. If informative bitmaps/graphics or unresolved visual conflicts exist, probe actual image capability early and preserve the existing no-false-viewing safeguards.

FULL_DOUBLE_READ still independently checks every in-scope unit; KEY_CLAIMS still checks all registered claims, their dependency chain and the planned ordinary sample. Acquisition route does not reduce either scope. Retain the same actual reviewer for incremental repairs.

Manifest, preserved history, page files, data files and any resolution evidence belong to the inspected scientific packet. Finish extraction, appends and all content updates before preflight/review. Source, native-element or resolution-evidence changes invalidate affected interpretation and previous acceptance; recheck the dependency chain and take a fresh actual snapshot. Do not regenerate extraction during review or refresh old approval tokens. Old batches and frozen trials stay unchanged.
